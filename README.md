# yuGoHA

Репозиторий Home Assistant App и встроенной интеграции **yuGoHA 0.5.1**.

yuGoHA — локальная система уведомлений для Home Assistant и Android без центрального облака yuGoHA. Пользователь устанавливает только Home Assistant App; интеграция `yugoha` устанавливается и настраивается автоматически.

## Возможности и совместимость с Android

- отправка уведомлений действием `yugoha.send`;
- доставка новых сообщений через Firebase пользователя и FCM;
- локальные HTTP/WebSocket, история, прочтение, удаление и синхронизация;
- работа при сером IP/CGNAT без белого IP;
- полная совместимость существующих автоматизаций и сопряжённых телефонов.

Android **yuGoHA 1.1.0** поддерживает профили нескольких домов: один телефон можно подключить к двум HA, а два телефона — к одному HA. История и синхронизация разделены по дому. Android **1.0** продолжает работать с одним сервером через прежние API.

## Установка и обычная отправка

Добавьте `https://github.com/yura2507/yugoha-ha` в магазин приложений Home Assistant и установите App **yuGoHA**. При первом запуске App автоматически устанавливает интеграцию и один раз перезапускает Home Assistant Core.

```yaml
action: yugoha.send
data:
  message: "1.info. Проверка yuGoHA"
```

## Новое в сервере 0.5.0

В Web UI каждому телефону можно назначить необязательное имя `recipient`, после чего сервер маршрутизирует FCM и WebSocket-сигнал только соответствующим устройствам:

```yaml
action: yugoha.send
data:
  message: "Открыта дверь"
  recipient: "yura"
```

Пустой или отсутствующий `recipient` по-прежнему означает отправку всем. Неизвестный получатель безопасно даёт ноль адресатов. Это уже работает со старым Android 1.0, потому что выбор устройств выполняет сервер.

Для подключения нескольких HA-серверов используйте Android 1.1.0 с профилями домов.

## Изменения 0.5.1

- `server_id` и `server_name` передаются также при удалении через FCM/WebSocket и в ответах синхронизации и обновления токена. Старые поля сохранены.
- Имя сервера можно задать параметром `server_name` в настройках HA App; идентификатор сервера при переименовании сохраняется.
- Новые адресные сообщения доступны в истории только телефонам, входившим в группу получателя в момент отправки. Последующая смена имени группы не открывает старую адресную историю другому телефону.
- Прочтение остаётся отдельным для каждого телефона. Удаление остаётся общим для устройств, которым доступно сообщение, в пределах одного HA.
- Попытка прочитать или удалить чужое адресное сообщение отклоняет весь запрос синхронизации с HTTP 403 до любых изменений.

История, созданная до обновления, остаётся общей: в версии 0.5.0 адресаты сообщений не сохранялись, и восстановить их достоверно нельзя. Изоляция адресной истории действует для новых сообщений после обновления.

Для нескольких домов каждый HA использует свой профиль сопряжения и ту же Firebase-служебную учётную запись проекта Android. Числовые ID сообщений уникальны только внутри своего сервера.
