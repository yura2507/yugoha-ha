# yuGoHA 0.5.1 — установка и настройка

## Установка и совместимость с Android 1.1.0 и 1.0

1. Откройте **Настройки → Приложения → Магазин приложений**.
2. Добавьте репозиторий `https://github.com/yura2507/yugoha-ha`.
3. Установите и запустите App **yuGoHA**.
4. При первой установке дождитесь единственного автоматического перезапуска Home Assistant Core.
5. В Web UI загрузите `service-account.json` своего Firebase-проекта.
6. В Android укажите локальный адрес, например `http://192.168.1.200:8098`, введите код сопряжения и подключите телефон.

Android получает FCM-уведомления вне локальной сети и использует HTTP/WebSocket для истории, прочтения, удаления и синхронизации. Android 1.1.0 поддерживает отдельные профили домов; Android 1.0 продолжает работать с одним сервером. Центрального облака yuGoHA нет; Firebase-проект принадлежит пользователю. Старые API, поля и автоматизации сохранены.

Обычная отправка всем устройствам:

```yaml
action: yugoha.send
data:
  message: "1.info. Проверка yuGoHA"
  title: "Home Assistant"
  priority: 5
```

## Новые возможности сервера 0.5.0

В Web UI в карточке телефона заполните поле **Получатель**, например `yura`. Одно имя можно назначить нескольким устройствам.

```yaml
action: yugoha.send
data:
  message: "Открыта дверь"
  recipient: "yura"
```

Сервер отправит FCM и WebSocket-сигнал только устройствам с `recipient: yura`. Если поле отсутствует или пустое, сообщение отправляется всем как раньше. Неизвестное имя не ломает автоматизацию: ответ успешный, адресатов и доставок — 0.

Android 1.0 менять для серверной маршрутизации не нужно. Для нескольких HA-серверов используйте Android 1.1.0 с профилями домов.

## Несколько домов и телефонов: 0.5.1

В Android 1.1.0 добавьте профиль для каждого дома и сопрягайте его с соответствующим HA отдельно. Для двух телефонов повторите сопряжение на каждом телефоне с одним и тем же HA. У серверов независимые БД и данные сопряжения устройств; один FCM token телефона можно зарегистрировать на нескольких HA. На каждом HA загрузите `service-account.json` того же Firebase-проекта, который настроен в приложении Android. Имя дома можно задать через параметр App `server_name`; оно не заменяет постоянный `server_id`.

Для новых адресных сообщений сервер сохраняет список выбранных телефонов в момент отправки. Смена `recipient` или подключение нового телефона позже не открывает чужую старую адресную историю. Неизвестный `recipient` создаёт сообщение с пустой аудиторией и нулём доставок. Сообщение без `recipient` остаётся общим, в том числе для будущих устройств.

Старая история до обновления сохраняется общей: предыдущие версии не записывали адресатов. Сервер не пытается угадать их при миграции.

Существующие ID сообщений при запуске больше не переписываются. Если предыдущая версия уже присвоила ID из диапазона временных меток, они сохраняются без преобразования: Android продолжает использовать прежние ID и курсоры.

Прочтение сохраняется отдельно для телефона. Удаление сообщения одним адресатом удаляет его для всей его аудитории на этом HA; остальные дома не затрагиваются. Чужие `read_ids`/`delete_ids` приводят к 403 без частичного применения запроса.

Ответы `/api/sync` и `/api/device/token`, новые и удаляющие FCM, WS `hello`/`message`/`delete` содержат `server_id`/`server_name`. Android 1.0 может игнорировать эти дополнительные поля. При работе со старым сервером 0.5.0 удаляющий FCM не содержит идентификатора сервера: Android с несколькими домами должен синхронизировать профили, а не удалять локальное сообщение по одному числовому ID.

## Проверка совместимости

Пройдены 17 автоматических серверных проверок: миграция старой БД и старого клиента, аудитория адресных сообщений, независимость прочтения телефонов, удаление, идентификатор сервера и постраничная синхронизация при конкурентных изменениях. Проверки используют реальные Flask и SQLite; внешние FCM/WebSocket-адаптеры подменяются для запуска без сети. Это не проверка доставки на установленном Home Assistant и физических телефонах.

## Ограничение внешнего доступа

Версия 0.5.1 не добавляет авторизацию к административному Web UI. Прямое открытие порта 8098 в интернет раскрывает административный интерфейс; используйте доверенную локальную сеть или защищённый доступ. Изменения защиты Web UI в эту версию не входят.
