# yuGoHA 0.5.1

Локальный сервер уведомлений для Home Assistant и Android yuGoHA без центрального облака.

## Возможности и совместимость с Android

Home Assistant App автоматически устанавливает/обновляет встроенную интеграцию, регистрирует discovery, при первой установке один раз перезапускает Home Assistant Core и предоставляет действие `yugoha.send`.

Сохраняются все функции версии 0.4.5: FCM через Firebase пользователя, локальные HTTP/WebSocket, история, read/delete и синхронизация. Белый IP не требуется; при CGNAT новые сообщения приходят через FCM.

Android **1.1.0** добавляет профили домов для подключения одного телефона к нескольким HA. Несколько телефонов можно сопрячь с одним HA. Android **1.0** сохраняет поддержку одного сервера через прежние API.

`Home Assistant → yugoha.send → yuGoHA App → Firebase пользователя → FCM → Android`

## Новые возможности сервера 0.5.0

- nullable-поле `recipient` безопасно добавляется к существующей SQLite-базе;
- получатель назначается каждому телефону в Web UI;
- `recipient` в `yugoha.send` выбирает одно или несколько устройств с этим значением;
- отсутствие/пустое значение отправляет всем, как раньше;
- неизвестный получатель не вызывает ошибку и возвращает ноль доставок;
- необязательные `server_id`/`server_name` заложены для будущего multi-server.

Маршрутизация `recipient` совместима с Android 1.0: её выполняет сервер. Для нескольких HA-серверов используйте Android 1.1.0 с профилями домов.

## Исправления 0.5.1

Идентификатор и имя сервера добавлены в события удаления FCM/WebSocket и ответы sync/token. В настройках App доступен `server_name`; переименование сохраняет `server_id`.

Аудитория нового адресного сообщения сохраняется при отправке. Только выбранные телефоны получают его историю и могут отметить его прочитанным или удалить. Прочтение учитывается отдельно для каждого телефона; удаление остаётся общим для аудитории сообщения на этом HA. Запрос с чужими ID отклоняется целиком (403).

Старая история остаётся общей, поскольку прежний сервер не сохранял адресатов сообщений. Это правило миграции; новые адресные сообщения после обновления уже изолированы. Отправка без `recipient` остаётся общей, включая телефоны, добавленные позднее.
